# Competitive Objectives — GoreeCloud DNS

## Purpose

GoreeCloud DNS uses mature DNS products and components as benchmark references while preserving GoreeCloud's own architecture, identity, privacy model, security boundaries, and implementation ownership.

A competitive objective is not a claim that the corresponding capability is currently implemented.

## Primary Benchmark Products

- Technitium DNS Server.
- AdGuard Home.
- Pi-hole.
- Unbound.
- Other mature recursive, authoritative, encrypted-DNS, filtering, DHCP, and policy platforms where they provide relevant public behavior or standards-based reference points.

## Capability Objectives

GoreeCloud DNS should study and, where justified by GoreeCloud requirements, match or exceed mature solutions in:

- Recursive resolution correctness and resilience.
- Authoritative DNS depth.
- DNSSEC validation and signing.
- Encrypted DNS support.
- Filtering flexibility.
- Threat-intelligence and RPZ support.
- Per-client and per-group policy depth.
- DHCP and local network integration.
- Query visibility and diagnostics.
- Cache performance and failure resilience.
- Automation and API coverage.
- Multi-server administration and high availability.
- IPv4/IPv6 and modern DNS record/protocol support.
- Deployment portability and operational maintainability.

## GoreeCloud Differentiation Objectives

GoreeCloud DNS should differentiate through:

- Privacy-first defaults and configurable data retention.
- Self-hosting without a mandatory commercial account.
- Full recursive operation without dependence on one third-party public resolver.
- Local ownership and exportability of DNS data and configuration.
- Deep first-party GoreeCloud platform integration.
- Consistent Glaze UI administration.
- Privacy Shield and Wardveil Security integration within their proper authority boundaries.
- Everkeep-aligned recoverability.
- Explicit separation of user DNS access from administrative authorization.
- No advertising or sponsorship-driven DNS behavior.

## Deliberate Boundaries

GoreeCloud DNS should not copy proprietary source code, protected assets, trade dress, or confidential implementation details from benchmark products. Public behavior, open standards, official documentation, and appropriately licensed open-source implementations may inform independent GoreeCloud engineering.

Feature breadth must not override privacy, security, correctness, maintainability, recoverability, accessibility, or truthful lifecycle status.
